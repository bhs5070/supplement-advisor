# M2 착수 기록

2026-11-11. Skill 설치 완료 후 사용자가 **“M2 시작하자”**라고 지시했다. 이전 보류는 해제됐다. 이 파일은 코드 조사·상태 기록이며 승인된 상세 설계나 구현 계획이 아니다.

## 보존할 합의

- 제품 Supervisor1개와 고정 전문5역할: 성분·함량·표시, 기능성 근거·광고, 개인 적합성, 안전성, 공식 정보·품질. 필요한 역할만 선택하고 조사 행동·근거 검토·한정 재조사·종료를 결정한다. 정해진5함수를 무조건 한 번 호출하는 흐름으로 대체하지 않는다.
- 공통 제품 점수는1~5정수로 설명하되 정보 부족은 감점 대신 산정 보류다. 추천·보류·비추천은 별도 근거 조건이다. 고정 가중합·점수 커트라인은 합의하지 않았다. 비회원 개인 적합성은 미평가다.
- React/TypeScript/Vite, FastAPI, PostgreSQL, Celery/Redis, HTTPX, LangGraph, 서비스 GPT-5.6 Luna와 확정 근거 출처를 유지한다. 회원·이미지 입력은 M3다.
- 활성180초·총20도구호출·역할당6·동시전문3·재지시총2/동일역할1, 누적 예산·claim fencing·복구를 보존한다. 제한 숫자와 구체 계수/예약 구현 계약은 구분한다.

## 실제 코드 확인

| 경계 | 현재 구현 | M2에 필요한 내용 |
|---|---|---|
| Worker | tasks.py의 claim→시도창 예약→수집/그래프→finish | 조사 그래프 연결과 부분 결과·복구 계약 |
| LangGraph | collection_graph.py의 observe→extract→official→report | Supervisor 선택·역할 조사 결과·근거 검토·재조사/종료 상태 |
| 예산/저장 | repository.py 원자 예약·fenced snapshot/finish | 병렬 역할과 Supervisor의 예산 계수·상태 저장 |
| API/보고서 | collection_only, score=null, verdict=hold | 수집 보고서와 구분되는 조사/평가 계약 및 호환 |
| 화면 | CollectionReport 타입과 수집 보고서 표시 | 조사 출처·역할별 결과·한계·평가 상태 표현 |
| 외부 근거 | I0030 대조 구현, Tavily 설정 필드 | 문헌/공식 자료 도구와 실제 요청·출처 검증 |

Tavily·OpenAI·식품안전나라 설정 존재 여부만 확인했다. 키는 출력하지 않았고 인증 성공·외부 응답·연동 완료로 해석하지 않는다. 외부 호출은0이다. 기존20URL 평가의 부족한 식별·함량 정보를 M2 확정 사실로 승격하지 않는다.

## 설계 전에 필요한 결정

1. 첫 구현 순서: 조사·출처 흐름을 먼저 검증할지, 점수/추천 설명 기준을 먼저 확정할지.
2. 각 역할의 입출력과 사용할 근거, Supervisor의 호출·재조사·종료 판단.
3. 모델/도구 요청의 예산 계수, 병렬 시간 예약, 부분 실패·복구 결과 합성 계약.

첫 순서를 사용자에게 비교표로 제안한 뒤 구체 설계를 작성한다. 중요한 설계는 EGM 독립 검토를 적용하고 발견 사항을 자동 반영하지 않는다. 승인 뒤 Superpowers writing-plans→구현/TDD→작성자 분리 검증 루프로 진행한다. 기존 Git은 최초 커밋 전이므로 worktree나 commit 기반 검증을 이미 가능하다고 가정하지 않는다.

## 실행 상태

Luna 구현 전문 Agent를 새 컨텍스트로 실제 호출해 읽기 전용 조사를 마쳤다. 소유 수정 파일은 없으며 하위 Agent·외부 호출·제품 코드 변경은 없었다. `.venv/bin/python -m pytest tests/test_agents.py tests/test_supplement_agents.py tests/test_api_worker.py -q --tb=short`는75 passed/2.56s였다. 이는 격리 DB·모의 네트워크 기반 기존 회귀이며 M2 실제 연동 검증이 아니다. 상세 설계 승인·구현·배포는 아직 수행하지 않았다.

사용자에게 첫 순서 A(조사 흐름 먼저, 점수·추천은 M2 후속)와 B(평가 기준 먼저, 조사·평가를 함께 구현)를 비교표로 제시했고 사용자가 **“A 가자”**로 A를 선택했다. 이는 M2 최종 범위에서 평가를 제외하는 선택이 아니다.

[M2-A 상세 설계 초안](superpowers/specs/2026-11-11-m2a-evidence-review-design.md)을 작성했다. 새 컨텍스트의 별도 Luna builder check는 충분성 게이트·정보부족 작업 상태·재조사 수명주기3개를 질문했다. 기존 M1 계약을 보존하는 내용으로 명확히 했고 재확인에서 중요한 미해결이 없다는 보고를 받았다. [검토 기록](reviews/m2a-builder-check.md)을 따른다. 이는 EGM 전체 리뷰나 구현 검증이 아니다. 사용자 상세 설계 승인, 구현 계획, EGM 실행 범위, 제품 코드 구현·새 테스트·실연동은 아직 남아 있다.
