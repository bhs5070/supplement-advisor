## 표본과 실행

root 소유 `m1-corpus.json`을 baseline 전에 20개/3~5사이트로 freeze하고 원본 바이트 SHA256을 결과에 기록한다. 실패한 표본은 교체하지 않으며 원래 분모20을 유지한다. URL이 삭제/차단돼도 결과로 남긴다. 추가 편의표본과 이전 ER/KGC 진단은 이 baseline에 합치지 않는다. 표본은 대표 무작위 표본이 아니므로 일반 성공률로 확대하지 않는다.

단계는 무모델 수집·직접 표 관찰 → 라벨 고정 → 명시 opt-in 모델/공식 API 측정이다. URL별 생성 모델 요청 최대1회, SDK 재시도0, 공식 검색은 기존 bounded budget을 따른다. 실패를 성공으로 바꾸기 위한 동일 baseline 재시도는 없다. 치명 수정 재검사는 원래 결과와 새 코드/실행 식별자를 함께 보존하며 최초 분모·원래 실패를 지우지 않는다. 키 설정 bool을 실제 호출 수로 세지 않는다.

## 라벨과 측정

평가 라벨은 모델 호출 전에 독립 페이지 관찰·필요한 공식 원문으로 정한다. 모델 입력은 URL 페이지 원문만이며 라벨·공식 record를 추출에 주입하지 않는다. 정답을 확보하지 못한 항목은 unjudged다. unknown을 incorrect 또는 correct로 바꾸지 않는다.

다음 분모를 따로 보고한다: 전체20, 수집 시도/성공, 모델 실제 요청/완료, grounded 추출 유효성, identity 필드별 관찰 가능/정답 라벨/일치·불일치·미추출·미판정, 신고번호·제조사·이름 확보, 공식 조회 시도/완료/matched/candidate/unverified/unknown, 독립 정답이 있는 공식 match 중 true/false/unjudged. `false_match=0`이어도 judged 표본이 없으면 안전성 검증 완료로 해석하지 않는다. 수집/모델/공식의 시간과 실제 도구 호출 수를 이유 코드별로 남긴다.

## 종료와 M2

1~2일 상한 안에 고정20개 baseline과 독립 QA를 마치고, 관찰된 치명 오류(잘못된 공식 확정·비근거 값·정보부족을 성공으로 위장·비밀 누출·권한/예산 회귀)를 우선 수정한다. 성능이 낮다는 이유만으로 지원 범위·예산·모델·수집 기술을 계속 넓히지 않는다. 남은 치명 오류가 있으면 M2 진입을 막는 이유와 최소 수정만 기록한다. 치명 오류가 해결되면 관찰된 지원/부분지원/미지원 사이트와 검증 한계를 공개하고 M2로 진행할 수 있다. 이는 M1의 일반 정확도 보증이나 전체 제품 평가 완료가 아니다. 판정은 측정 결과·정답 커버리지·남은 오류를 보고 결정하며 사전 성공 임계치를 꾸며내지 않는다.
