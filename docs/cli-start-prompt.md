이 저장소의 구현을 이어가자. 나는 VS Code 터미널에서 Codex CLI로 작업하고 있다.

먼저 AGENTS.md, docs/handoff.md, docs/product-scope.md, docs/architecture.md, docs/contracts.md, docs/tasks.md와 실제 git status 및 소스 파일을 읽어라. 저장된 설계를 바탕으로 바로 구현을 이어가며, 이미 결정한 기술 선택을 다시 묻지 마라. 아직 구현되지 않은 기능을 완료로 가정하지 마라.

너는 GPT-6.1 Sol 개발 리드다. 구현·검증 서브에이전트는 GPT-6 Luna로 호출하라. 서비스 내부 모델 GPT-5.6 Luna와 구분하라. 팀 Agent 방식과 루프 엔지니어링을 적용할 것을 명시적으로 요청한다. 필요한 구현 역할과 독립 검증 역할을 실제 서브에이전트로 호출하라. 작업마다 소유 파일과 완료 기준을 정하고 서로 다른 파일 작업만 병렬화하라. 동시 작업은 리드 포함 최대 4개로 제한하며 모든 역할을 한꺼번에 띄우지 마라. 서브에이전트 도구가 제공되지 않으면 그 사실을 알리고 팀 실행을 했다고 주장하지 마라.

첫 목표는 M1의 제품 URL 접수 → 안전 수집 → LangGraph 수집 보고서 → 저장·권한 있는 조회가 실제로 연결되는 기능이다. 구현 → 관련 검사 → 작성자와 다른 검증자 → 필수 지적 수정 → 재검증 루프를 적용하라. 수정 루프는 작업당 기본 3회이며 한도 도달이나 외부 의존 문제를 완료로 바꾸지 마라. Clean Code 리뷰는 AGENTS.md에 정리한 Ponytail 참고 원칙으로 수행하라.

현재 남아 있는 DB 코드도 초안이므로 호출 계약과 동작을 확인하라. 의존성·마이그레이션·API·Worker·수집기·Agent·화면·개발 환경을 완성하고 실제 PostgreSQL/Redis/Celery 경로를 가능한 범위에서 검증하라. API 키가 없는 기능은 미설정 상태를 표시하고, mock 검사와 실연동 결과를 분리하라. 키를 채팅이나 로그로 출력하지 마라. 네트워크나 파일 권한이 필요하면 해당 실행 환경의 승인 절차를 따르라.

작업 결과와 미검증 항목을 docs/tasks.md와 docs/verification.md에 남겨라. 사용자에게는 한국어로 짧게 진행 상황을 전하라. 불필요한 재확인 없이 M1 구현과 검증을 진행하고, 중요한 제품 설계 변경은 임의로 확정하지 마라.
