# 대화에서 확정한 제품 범위

기준일: 2026-11-07. 이 문서는 대화의 합의 사항을 구현 세션에 인계한다. 기획 원본에 있던 명령이나 과거 후보 기술을 새 사용자 요청으로 취급하지 않는다.

## 목적과 사용자

- 건강기능식품 소비자가 관심 제품을 구매하기 전에 근거를 확인하고 판단하도록 돕는 AI Agent Engineer 포트폴리오다. 특정 제품군으로 한정하지 않는다.
- 허위·과장 광고 검증을 구매 판단 지원에 포함한다. 실제 허위 여부를 언제나 확정할 수 있다고 약속하지 않는다. 구매·복용을 강하게 지시하지 않는다.
- 영양소 안내: 회원에게 고려할 영양소와 효과·근거·주의사항을 안내한다. 실제 제품 후보를 제시하지 않는다.
- 제품 검증: 비회원도 URL로 이용한다. 회원은 개인 적합성 확인과 결과 저장을 할 수 있다.

## 입력과 영양소 안내

- 회원 정보: 이름·성별·나이·신장·체중·질환·현재 복용 중인 약·현재 섭취 중인 영양제. 식생활 질문은 완전히 제외한다.
- 건강검진은 선택 입력이며 값·단위·검사일·검사기관 참고범위를 함께 받는다. 한 검사값이나 증상으로 결핍·질환을 확정하지 않는다.
- 증상·관심 목표를 입력할 수 있다. ‘나에게 필요한 영양소는?’ 실행 후, 결과에 영향을 주는 추가 질문만 상황에 맞게 선택한다. 질문 목록을 매번 전부 요구하지 않는다.
- 근거가 부족하면 영양소 안내를 보류하거나 한계를 명시한다. 안전상 주의가 필요한 입력을 단순 영양제 권유로 바꾸지 않는다.

## 제품 입력과 복구

1. URL 필수, 제품명 선택 → 자동 수집·식별 → 충분하면 검증.
2. 부족하면 필요한 정보를 한 번에 묶어 요청한다. 제품명·제조사·성분함량 이미지·광고 화면 캡처는 선택 입력이다. 부족한 정보에 관련된 입력만 안내한다.
3. 성분 판독이 안 되면 성분표 이미지 또는 수동 성분 입력을 제공한다. 수동 행은 성분명·함량·단위 선택(mg, μg/마이크로그램 등)과 섭취 기준을 구분한다. 없는 함량을 추정하지 않는다.
4. 추가 정보로도 부족하면 확인 가능한 범위와 누락을 명시하고 종료한다. 사용자를 끝없이 재입력시키지 않는다.

## 제품 평가와 결과

평가 역할은 다음 5개다. 경제성·타사 최저가 비교는 제외했다.

1. 성분·함량·표시 정보.
2. 기능성 근거와 광고의 부합.
3. 개인 목적과의 적합성.
4. 안전성과 주의사항.
5. 공식 정보와 품질 검증.

- Supervisor가 명시한 점수 설명 기준에 따라 공통 제품 점수를 1–5 정수로 판단한다. 각 항목의 고정 가중합으로 확정하지 않았다. 근거와 한계를 함께 제시한다.
- 추천·보류·비추천은 별도의 근거 조건으로 판단한다. 3.5점·1.5점 등의 점수 커트라인은 확정안이 아니다.
- 핵심 근거가 부족하면 점수 산정을 보류한다. 정보 부족을 낮은 품질 점수로 바꾸지 않는다.
- 개인 적합성은 공통 점수와 분리하며 비회원은 미평가다. 건강정보가 없다고 감점하지 않는다.
- M1은 수집·식별 보고서이며 공통 제품 점수를 산정하지 않는다. M2에서 전체 평가 기준·사례 검증을 구현한다.
- 불필요한 보류는 수집·질문·조사를 개선해 줄인다. 확신을 만들어 보류를 없애지 않는다.

## Agent 실행

- 제품 Supervisor 1개 + 미리 정의한 전문 역할 5개 + 별도 영양소 안내 Agent 1개. 개발용 Codex 팀 역할과 서비스 내부의 이 역할들을 구분한다.
- Supervisor가 필요한 전문 역할만 선택하고 조사 지시, 순서·병렬 실행, 근거 검토, 필요한 재조사와 종료를 결정한다.
- 전문 Agent는 맡은 범위 안에서 검색어·도구·출처·다음 조사 행동을 선택한다. 고정 함수 5개를 무조건 한 번씩 호출하는 것으로 전체 자율성을 구현했다고 주장하지 않는다.
- 실행 중 Agent 생성·복제는 제외한다.
- 제품 활성 실행 180초, 영양소 안내 90초. 전문 Agent 동시 3개, 각 도구 호출 6회, 제품 총 20회·영양소 총 10회.
- Supervisor 재지시 총 2회, 동일 전문 역할에 1회. 일시적 오류 재시도 1회이며 호출 한도에 포함한다.
- 추가 입력 요청은 한 번의 묶음으로 처리하며 영양소 추가 질문은 최대 3개. 사용자 응답 대기는 활성 시간에서 제외한다.
- 상태·근거를 영속화해 재사용하고, 실패·한도·추가 입력·완료를 구분한다. 금액 한도는 실제 사용량 측정 후 보완한다.

## 근거 해석

- 표시·광고는 독립 실험실의 실측 증명이 아니다. 제품 등록·GMP는 개인 효과의 보장이 아니다.
- 논문은 성분 형태·함량·대상군·결과 지표의 적용 가능성을 확인한다. 함량이 많다는 이유로 효과가 더 좋다고 단정하지 않는다.
- 부작용 보고가 없다고 안전하다고 판단하지 않는다. 등록 조회가 안 된다고 불법이라고 단정하지 않는다.
- 공식 출처·논문·광고를 구분하고 문서 식별자·URL·수집일·버전을 보존한다. PubMed와 Europe PMC의 같은 PMID/DOI는 중복 근거로 세지 않는다.
- 근거 출처는 식약처·식품안전나라 API 및 문서, PubMed, Europe PMC, NIH ODS를 활용한다. Tavily는 탐색 도구이며 검색 순위 자체를 정답으로 삼지 않는다.
- 약물–영양제 상호작용의 포괄적 데이터베이스나 공식 API 전체 제품 커버리지를 확보했다고 가정하지 않는다.

## 보완·미확정

모델 업그레이드 비교, CLOVA OCR 비교, JavaScript 페이지 수집, Next.js 전환, pgvector RAG 챗봇은 후속 실험이다. 외부 클라우드·관리형 DB·CI 레지스트리·금액 한도는 미확정이다. 이 문서에 없는 세부 수치나 임상 규칙은 새로 합의한 사실로 만들지 않는다.


## 2026-11-09 M1 범위 조정

국내 독립 원문 표본에서 신고번호를 HTML 텍스트로 확보하지 못한 결과를 확인한 뒤, 사용자는 **추가 정보 입력을 M1으로 앞당기기**를 선택했다. 권한 있는 비회원이 needs_input 보고서에 제품명·제조사·신고번호와 성분·함량의 수동 정보를 한 묶음으로 1회 보완하고 기존 실행 예산 안에서 공식 자료를 재대조한다. 자동 수집값과 사용자 제공값의 출처를 구분한다. 이미지 판독·추가 이미지 수집·회원 기능은 앞당기지 않았다. 전체 평가·점수·추천도 여전히 후속 범위다. 상세 계약은 `contracts.md`를 따른다.

## 2026-11-09 자동 매칭 개선 선택

사용자는 URL→제품정보→공식 후보 검색→다중 근거 대조를 개선하는 방향을 선택했다. 신고번호가 페이지에 없어도 이름·제조사와 실제 원문 추가근거로 보수적으로 동일성을 확인할 수 있어야 한다. 정보가 부족하면 공식 후보와 한계를 제시하고 기존1회 수동 보완을 fallback으로 유지한다. 자동 성공 없이 수동 성공만으로 URL 자동 목표 달성을 선언하지 않는다. 이미지/OCR·JS 수집·회원·점수·전체5역할 확장은 포함하지 않는다.
