2026-11-11. 사용자는 설치 계획을 확인하고 `ㄱㄱ`로 승인했다. 적용 작업공간은 `/Users/hyeonseokbae/Desktop/ad_fact_check`다. 이번 범위는 Skill 설치·호환성·정책 통합·검증이다. 제품 기능, 아키텍처, 에이전트 구성과 모델, 환경 변수, 빌드·실행 설정, 데이터와 DB는 변경하지 않는다. M2는 보류다.

| STE-inspired | 명확한 결과 전달 | 작업·오류·테스트·검증·인계 보고 | 고정 양식을 매번 강요하지 않음 |

## Superpowers

설치된 `using-superpowers`부터 확인하고 관련 Skill을 읽는다. 개념상의 기본 흐름은 요구/설계 명확화 → 계획 → 실행과 TDD → 리뷰 → 검증 → 마감이다. 실제 순서·승인·필수 조건은 설치 버전이 정한다. 사용자의 상세 요구와 기존 문서·승인 기록을 먼저 읽어 불필요한 질문과 중복 설계 문서를 줄인다.

- 기능·버그·동작 변경 등 TDD 적용 작업은 실패 테스트를 실제 관찰한 후 최소 구현하고 GREEN 뒤 리팩터링한다. 실행하지 않은 RED/GREEN을 주장하지 않는다.
- 작업 규모·공식 지원 경로에 따라 `subagent-driven-development`와 `executing-plans`를 선택한다. 기존 작성자/검증자 분리, 소유 파일, Sol/Luna 모델과 리드 포함 최대4개를 유지한다. 설치 자체는 새 에이전트 생성 권한이 아니다.
- 현재 호스트의 실제 도구와 모델 허용 목록을 확인한다. Skill 예시만 보고 multi_agent·모델·reasoning 설정을 추가하거나 바꾸지 않는다.
- 기존 작성 코드와 미커밋 파일은 보존한다. 과거 초안을 TDD 원칙을 이유로 지우지 않는다. 이후 작업에서 충돌하면 최소 변경 대안을 제시한다.
- 최초 커밋이 없는 현재 저장소에서는 worktree·commit 범위 리뷰·브랜치 마감의 완전한 실동작을 입증하지 못했다. 설치를 위해 최초 커밋이나 Git 설정을 만들지 않는다.
- 이번 설치/지침 변경은 승인된 설정 작업이다. 제품의 RED-GREEN 사이클을 수행했다고 주장하지 않으며 설치 진단·인식·보존 검사를 사용한다.

## EGM

Superpowers의 승인 대상 설계 초안을 재사용한다. `egm-review`를 우선 고려하고 아이디어 탐색이 필요한 경우만 `egm-brainstorm`을 사용한다. 중요한 설계인지 애매하면 먼저 제안한다. 내부 서브플로도 포함해 실제 반복 필요와 실행 범위를 확인한다. `egm-review-loop`는 일반 작업의 기본값이 아니다.

검토 결과는 Blocker/Major/Nit 등 실제 중요도로 정리한다. 모든 발견 사항을 자동 수정하지 않는다. 설계·코드 변경은 사용자 승인 후 한다. 낮은 중요도만 남았다고 무한 반복하거나 변경 없는 설계를 재검토하지 않는다. 공식 보고서·필수 승인 절차는 유지한다. 영어 작성 지침보다 사용자가 요청한 한국어를 우선한다.

Goldfish는 대화 이력을 전달하지 않는 새 컨텍스트로 실행해야 한다. 사용 시 실제 지원 도구의 `fork_turns: "none"` 등으로 확인한다. 같은 컨텍스트의 자기 검토를 독립 검토라고 부르지 않는다. 파일시스템·AGENTS.md 제외까지 보장됐다고 주장하지 않는다. 이번 설치에서는 검토자 생성과 실제 설계 검토를 실행하지 않는다.

## Archify

아키텍처·서비스 관계·데이터 흐름·복잡한 워크플로·포트폴리오 다이어그램 요청에 사용한다. 시각화가 유용해도 요청되지 않았다면 먼저 제안한다. `[archify explainer: on-demand]`를 사용하며 자동 설명 페이지 모드는 켜지 않는다.

실제 코드베이스를 읽은 경우 파일과 데이터 흐름 근거를 반영한다. 구현된 구조·계획·가정·저장된 과거 실행 기록을 구분한다. 현재 저장소가 최초 커밋 전임을 숨기거나 Git 기반 출처 증명이 완료됐다고 하지 않는다.

인터랙티브 HTML을 우선하고 사용자 요청 시 지원 형식으로 출력한다. 필요한 최소 결과물을 만들며 UI UX Pro Max를 자동 호출하지 않는다. 설치는 공식 목록에서 `archify` 하나만 선택하고 Codex의 프로젝트 경로에 복사한다. 설치 진단은 `doctor`, 실제 결과물은 설치된 Skill의 `finalize`/검증 계약을 따른다. 자동 검사·브라우저 검사·캡처·사람처럼 화면을 읽은 시각 검토를 구분한다. 실패 종료를 성공으로 바꾸지 않는다. 요청 없는 설치/업데이트나 브라우저 의존성 추가를 하지 않는다.

## UI UX Pro Max

기존 React/TypeScript/Vite, 스타일·디자인 시스템·컴포넌트를 먼저 확인한다. 기존 자산을 재사용하고 색상·서체·간격·상태를 일관되게 유지한다. 키보드 조작, 접근성, 반응형과 실제 동작을 확인한다. 비즈니스 로직을 불필요하게 바꾸지 않는다.

새 페이지/제품 방향에는 설치 버전이 요구하는 디자인 시스템 검색을, 특정 UI 문제에는 가장 좁은 도메인/스택 검색을 사용한다. 검색 결과가 해당 제품과 플랫폼에 맞는지 확인하며 미검증 결과를 저장하지 않는다. 필요할 때만 디자인 대안을 생성한다. 단순 문구와 비시각적 백엔드 작업에는 실행하지 않는다.

승인된 공식 설치기는 핵심 Skill과 `banner-design`, `brand`, `design`, `design-system`, `slides`, `ui-styling`을 함께 설치한다. 이들은 프로젝트 UI/디자인 지원용이며 일반 작업의 자동 호출 대상이 아니다. 설치는 제품 UI 변경이나 디자인 시스템 생성 승인이 아니다.

## Karpathy와 STE

Karpathy 원칙은 AGENTS.md에 통합한다. 별도 Skill을 중복 설치하거나 별도의 반복 심사를 추가하지 않는다. 중요한 가정과 대안을 드러내고, 현재 요구에 필요한 가장 단순한 구조로, 관련 코드만 수정하며, 검증 가능한 목표로 완료를 판단한다.

기본 출력은 한국어다. 짧고 직접적인 문장·일관된 용어를 사용한다. 사실/가정/추측/미검증과 실제/모의/저장 원문 재검사를 구분한다. 검증 실행 여부·범위·결과와 중요한 기술적 맥락을 생략하지 않는다. 코드·변수·함수·로그 원문은 문체 때문에 수정하지 않는다.

완료·오류·검증·인계에는 적극, 설계·복잡한 학습에는 부분, 브레인스토밍·깊은 기술 토론에는 최소 적용한다. TASK/ACTION/EVIDENCE/VERIFICATION/RISK/NEXT를 필요한 경우만 사용한다. 설치 결과는 INSTALLED/CONFIGURED/VERIFIED/CONFLICTS/LIMITATIONS/NEXT로 보고하되 기계적인 빈 항목을 반복하지 않는다. 엄격한 ASD-STE100 표준 인증이나 준수를 주장하지 않는다.

## 충돌과 보존

사용자 명시 요구와 상위 지침, 안전성과 정확성, 실행 Skill의 필수 절차, 충돌하지 않는 기존 프로젝트 규칙, 일반 스타일 순으로 적용한다. 상위 지침의 권한을 낮추지 않는다. 필수 규칙이 충돌하면 위치·영향·최소 대안을 보고하고 변경 전 사용자에게 확인한다. 설치된 Skill은 사용자의 기존 설정 보존·범위 제한을 무효화하지 않는다.

기존 Skill은 유지한다. Archify를 시스템 시각화 기본값으로 하되 기존 visualize와 같은 결과물을 중복 생성하지 않는다. EGM 실행만으로 Archify를, Archify 실행만으로 UI Skill을 호출하지 않는다. `explain_me`와 `prompts.chat`은 제외한다. 사용량 절감을 이유로 필수 테스트·보안·무결성 검증을 생략하지 않는다.
